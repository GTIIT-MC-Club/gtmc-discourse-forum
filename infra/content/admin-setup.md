# 新站初始化：脚本做了什么，还剩哪些要手动

新装的论坛第一次部署时，`infra/deploy-discourse.sh` 会跑 `infra/discourse/` 下的初始化脚本，
把站点设置、版块、主题、侧边栏、徽章、引导机器人设成社团的出厂设置，然后在数据库里记下「已初始化」。
之后这些都归后台管理，再部署不会覆盖。论坛的配置整体怎么分工、怎么备份和回档，见仓库根目录的 `CONFIGURATION.md`。

本文记的是：初始化脚本各做了什么、出厂设置背后的考虑、初始化之后还要手动做的事。

---

## 一、执行顺序

| 顺序 | 脚本 | 做什么 |
|---|---|---|
| 1 | `site_settings.rb` | 站点设置、版块（简介、发帖模板）、信任等级门槛、自定义状态、引导机器人的欢迎私信开关 |
| 2 | `import_theme.rb` | 从 GitHub 的 `gtmc-forum-theme` 安装 GTMC 主题（远程主题），第一次安装时设为默认主题、浅色配色 GTMC Light 和深色配色 GTMC Dark（两套都允许用户自选） |
| 3 | `sidebar.rb` | 版块顺序和图标、默认侧边栏、「社区」区链接、页脚的站内链接 |
| 4 | `badges.rb` | 「社团成就」分组和四枚社团徽章，核心自带徽章的中文改名 |
| 5 | `narrative_bot.rb` | 引导机器人改名、头像、简介和教程台词 |

后一个脚本依赖前面的结果，缺了会报错退出。初始化中途失败时修好问题再跑一次部署脚本即可：
标记要全部跑完才写，已经建好的版块会被跳过。

每次部署都会跑、不属于初始化的有两个：`import_theme.rb` 更新主题代码（不碰主题设置和配色选择），
`guides.rb` 同步教程（见下文「新手教程」）。插件由 `app.yml` 的 `after_code` 钩子在重建容器时克隆，
插件合并到 `main` 后要 `deploy-discourse.sh --rebuild` 才会上线。

`import_theme.rb` 不需要传主题文件：容器里的核心直接从 GitHub 克隆，所以**执行它时容器要能连上 github.com**。
连不上时脚本报 `theme import ... failed` 退出，站上的主题保持原样。

`sidebar.rb` 只删除除了核心欢迎帖以外没有帖子的 General 版块，有人在里面发过帖就保留并打印 `kept category General`，
由管理员把帖子移走再在后台删掉。

**Logo 和图标要手动上传一次**（脚本不管）：后台 → 设置 → 品牌，按下表上传 `design/brand/` 里的文件，
其余品牌图片（`large_icon`、`mobile_logo`、`opengraph_image` 等）留空，核心会回落到下表里的图。

| 设置 | 文件 | 为什么是这个格式 |
|---|---|---|
| `logo` | `gtmc-logo.svg` | 页头的完整 Logo。SVG 按像素画成方块，任何缩放都不糊 |
| `logo_small` | `gtmc-logo-small.svg` | 页头收起后的方形小 Logo，同上 |
| `favicon` | `gtmc-favicon-32.png` | 核心要生成 32×32 的版本，但不会把 SVG 转成 PNG；Safari 也不认 SVG 网站图标 |
| `apple_touch_icon` | `gtmc-apple-touch-icon-180.png` | iOS 只认 PNG，且透明区域会被填黑，所以图里自带底色 |
| `manifest_icon` | `gtmc-app-icon-512.png` | 安卓「添加到主屏幕」用的 PWA 图标，同样要不透明 PNG |

PNG 都已经是核心要的精确尺寸、整数倍放大，核心不会再缩放，像素不会糊。
这些文件由 `design/brand/build_icons.py` 生成，改图改脚本里的像素表，再按脚本开头的命令重新生成。

「老玩家俱乐部」在默认侧边栏里，但它只对信任等级 2 及以上可见：核心按权限过滤，
新人的侧边栏里看不到它，升到 2 级后自动出现，不会点进去吃「无权访问」。

**新手教程以仓库为准**：「新人指南」版块里的教程帖由 `guides.rb` 从 `gtmc-forum-wiki` 仓库同步，
写法见那个仓库的 `README.md`。

- 首帖被锁定（核心的「锁定帖子」）：普通用户包括发帖人都不能编辑，回复照常。教程首帖也不再是 wiki。
- 管理员和版主仍然能编辑锁定的帖子，但下次同步会被仓库的版本覆盖，脚本会打印 `warning: ... last edited by <用户名>`。
  要改内容就改仓库里的文件。
- 每个文件对应的话题记在后台「永久链接」里（`wiki/launcher` → 话题），所以 `/wiki/launcher` 这类地址永远指向那篇教程。
  不要删这些永久链接，删了脚本会当成新教程再发一篇。
- 第一次同步时，版块里标题与某个文件完全相同的旧话题会被接管（打印 `adopted`），原来的回复保留，首帖换成仓库的版本。
- 仓库里删掉的教程，论坛上的话题不会被删，脚本只打印警告，由管理员决定怎么处理。

## 二、徽章

目标：让「发了好帖」「帮了别人」这件事在论坛上留下痕迹。徽章由 `badges.rb` 创建，名称、说明、图标、授予条件都写在脚本里。

| 徽章 | 等级 | 图标 | 授予方式 | 授予条件 |
|---|---|---|---|---|
| 初来乍到 | 铜 | 核心默认 | 自动（核心的信任等级 1 徽章，脚本只改中文名和说明） | 升到信任等级 1 |
| 建筑师 | 银 | 砖墙 | 自动，每天核对一次 | 在「建筑展示」发的作品帖里有上传的图片，且这篇帖子收到至少 3 个赞 |
| 红石工程师 | 银 | 齿轮 | 自动，每天核对一次 | 在「技术开发」发的帖子至少收到 1 个赞，并且在这个版块回复过别人发的话题 |
| 活动常客 | 铜 | 蛋糕 | 自动，每天核对一次 | 在「活动」版块里别人发的 3 个以上不同的话题下回过帖（即报名） |
| 引路人 | 金 | 指南针 | **手工授予** | 带会了至少一位完全的新手：对方的第一篇帖子或第一次进服是你带的 |

自动授予的几条是对原设计的**近似**，管理员要知道它看不到什么：

- 建筑师：看不出作品是不是原创。搬运的帖子被删后，下一次每日核对会收回徽章。
- 红石工程师：只检查有人点赞、回复过别人，看不出内容有没有用、回复算不算答到点上。
- 活动常客：「参加」只能近似成「报名」，核心不记录谁真的到场。
- 查询只统计公开版块里未删除的帖子（读核心的 `badge_posts` 视图），私信和受限版块不算。

新徽章最迟一天后才会出现（核心每天跑一次）。想立刻看到：在 `rails runner` 里执行
`BadgeGranter.backfill(Badge.find_by(name: "建筑师"))`。

**自动授予的徽章不能靠删除用户的徽章来收回**：只要条件还满足，下一次每日核对又会授予。要收回，处理造成条件满足的帖子（删帖、移出版块）。

**查询在后台看不到**：脚本不需要隐藏设置 `enable_badge_sql`，核心定时授予时也不检查它。
它只管后台徽章编辑页的「查询」输入框和预览，打开后任何管理员都能在页面上写任意 SQL，权限太大，所以保持关闭。
要看或改查询，读改 `badges.rb`。

**手工授予「引路人」**：后台 → 徽章 → 引路人 → 授予 → 填用户名 → 确认。

核心自带徽章只改了中文界面里显示的名称和说明（翻译覆盖），徽章本身不动：
信任等级 1 → 初来乍到，首个赞 → 点亮火把，首次链接 → 搭好第一座桥，首个表情 → 气氛组，
首次引用 → 引经据典，首次提及 → 喊人组队，首次分享 → 传送门。英文界面的用户仍看到英文原名。

## 三、引导机器人

核心自带的 discourse-narrative-bot 插件里的机器人原名 discobot，现在叫**小火把**（用户名 `gtmc_torch`），
头像是仓库里原创的像素火把（`infra/content/narrative-bot/avatar.png`，源文件和生成脚本在同一目录）。
新用户注册后自动收到教程私信，教完基本操作，结尾引导去「白名单与申诉」申请白名单、读「新人指南」。

- 初始台词在 `infra/content/narrative-bot/zh_CN.yml`，文件头写了哪些文字受插件代码约束、不能随便改。初始化之后改台词到后台「自定义 → 文本」搜 `discourse_narrative_bot`。
- 教程的流程（步骤顺序、每步怎么判定通过）由插件代码决定，改台词改不了它。
- 结业证书的图片模板没动，证书上机器人的署名随用户名变成 `gtmc_torch`。
- 只覆盖了中文台词；界面语言是英文的用户看到插件自带的英文。
- 已注册的用户不会补发教程；想再走一遍的话，给机器人发私信，它会回复怎么开始。
- 初始化之后想换名字或头像：在后台改机器人用户的用户名和头像。头像的源文件是 `avatar.txt`，改完运行 `ruby infra/content/narrative-bot/build_avatar.rb` 生成 `avatar.png` 再上传。

## 四、设置完之后的自查

- [ ] 未登录窗口里左侧栏的版块按 `sidebar.rb` 的 `CATEGORY_ICONS` 的顺序排列，每个前面是像素图标。
- [ ] 新注册的测试账号（TL0）点「白名单与申诉」能看到发帖模板，标题框有灰字提示。
- [ ] 测试账号看不到「老玩家俱乐部」。
- [ ] 「欢迎与社区规则」置顶帖发在「公告」并全局置顶；页脚的「新人指南」点开是「新人指南」版块，置顶的是教程目录。
- [ ] 页脚（任意页面拉到底）有社团名、三到四个链接和商标声明；「新人指南」「白名单与申诉」点得开；填了 `discord_invite_url` 之后多出「加入 Discord」。
- [ ] 页头左上角是社团的像素 Logo，放大浏览器也是清晰的方块边缘，不是糊的。
- [ ] 页面往下滚、页头收起后，左上角换成方形的草方块「G」；浏览器标签页的图标也是这个「G」。
- [ ] 把系统切到深色模式再打开论坛，是 GTMC Dark；浅色模式是 GTMC Light。用户的「偏好设置 → 界面」里能选这两套配色。
- [ ] 徽章页 `/badges` 能打开，最前面的「社团成就」分组里有建筑师、红石工程师、活动常客、引路人，图标是像素图标。
- [ ] 用户菜单（点头像 → 个人标签）里有「设置自定义状态」。
- [ ] 新注册一个测试账号，收件箱里有「欢迎来到 GTMC！我是小火把」的私信，发信人头像是火把。
- [ ] 「新人指南」版块里「新手教程目录」在版块内置顶；用测试账号打开任意一篇教程，首帖没有「编辑」按钮，能回复；末尾有「在 GitHub 上修改源文件」链接。
- [ ] 跑了一次 `sudo infra/export-forum-config.sh`，把初始化后的设置作为第一份备份提交进 `forum-config/`。
